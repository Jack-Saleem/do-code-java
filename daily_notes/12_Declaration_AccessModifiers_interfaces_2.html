Interface Methods

Every method inside of the Interface is by default public & abstract.
REASON: It's public to provide the accessablity to the classes fro implementation.
The implementation class is responsible for the implementation of that method.
The following method declarations are allowed inside the interface.

ALLOWED
void m1();
public void m1();
abstract void m1();
public abstract void m1();
As the method is by default on public and abstract, we can't declare the method with any orther access modifiers, like
private
protected
static
final
synchronized
strict fp
native.

Interface Variables

An interface can contain Variables
Every Interface variabl is public, static & static by default no matter we declare them or not. REASON:
public: To make available to every implementation class.
ststic: WIthout object also this implementation class has to access this variable.
final: A single variable is getting shared by all the objects,
if any of the implementing class changes the variable then the change will be applicable on the next classes also.

Access modifiers like private, protected, transient & volatile are not applicable to this.
For interface variables initialization is must and should during the time of declaration itself otherwise CE will rises.
Modification is not allowed due to Final Key Word.

Interface Naming Conflicts

If two interfaces contains same method name & return type then in the implementation class we just need to implement only once

If two interfaces contains same method name but different argument type then we must provide implementation for both the methods, which will overloads the methods

If two interfaces contains same method name but different return types then it's not possible to implement such classes unless the return types are co-varient

Interface variables also have this problem but this ambiguity issue can be overcome by calling object with the interface name.
