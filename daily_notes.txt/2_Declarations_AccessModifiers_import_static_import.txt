CASE STATMENTS TYPES:
There are two types of import statments
1. Explicit Import Statment
	ex:
	import java.util.ArrayList;
	
2. Implicit Import Statment
	ex:
	import java.util.*;
		This is not recomended to use, it reduces the readbility of the code.

When we try to use the class which is available in multiple packages, like we have 'Date' which is available in both the util * sql package.
An ambigious issue will araise like which package should be used, specifying the package is importsnt to avoid ambiguity issues.

Note: Defining the class or interface in package only includes the classes upto tha location they won't consider the sub classes onside them, if we want the sub class then we need to write the import statment until the sub package class level.

DEFAULT PACKAGES:
There are two default packages in java 
1. java.lang PACKAGE 
2. default PACKAGE[ classes in the current working directory] 

Classes and interfaces in this packages are by default available for every java program hence, no required to write any import statment.

Fully occupied name and import statment both takes same execution time but in terms of compilation fully occupied name is faster due to straight commands.

DIFFERNCE BETWEEN #include<> in C and import st in java:
When we do #include in C language then it loads all the i/p & o/p header files which make it a STATIC INCLUDE.
When we import the packages in java it only loads or imports the classes or interfaces in the package only when it is getting used. 
	we can say this as DYNAMIC INCLUDE (or) LOAD ON DEMAND (or) LOAD ON FLY.
	
STATIC IMPORT:
It was introduced in the 1.5V
Used to import static methods or static variables so we can use them directly.
It's not recomended to use unless we needed them
